# FJF-2026 clinical development programme

> **Simulated data · fictional compound.** FJF-2026 does not exist. Every FJF-2026 patient, result and number is generated by code in this repository. The one exception is the benchmark, which uses the public CDISC pilot study (see [Third-party data](#third-party-data)). Nothing here is medical advice or evidence about any real medicine.

A simulated clinical development programme for an oral add-on to metformin in adults with type 2 diabetes. It takes the fictional compound FJF-2026 through a phase II dose-finding study, a confirmatory phase III study and an integrated safety analysis. Everything is built to the standards and controls used in industry: CDISC data standards, ICH E9(R1) estimands, double programming and full reproducibility.

## The programme

| Study | Design | Question | Primary method |
| --- | --- | --- | --- |
| Benchmark | Public CDISC pilot study | Does the pipeline reproduce published results? | ADaM and table replication |
| FJF-2026-201 | Phase II, randomised, double-blind, placebo and four doses, 12 weeks | Which dose goes to phase III? | MCP-Mod |
| FJF-2026-301 | Phase III, randomised, double-blind, placebo-controlled add-on to metformin, 26 weeks | Is the selected dose effective? | ICH E9(R1) estimands, MMRM, reference-based MI |
| Integrated safety | Pooled 201 and 301 | What is the safety profile? | Safety tables, listings and figures |

Three principles hold the design together:

1. **Sealed truth.** The simulator draws its true parameters from a secret seed that the analysis code never reads. After each analysis is final, the truth is unsealed and compared with the estimates ([ADR 0018](docs/adr/0018-sealed-truth-and-data-generating-model.md); its limit is stated in [docs/ai-assistance.md](docs/ai-assistance.md)).
2. **Messy raw data.** The simulator produces EDC-like data with partial dates, out-of-window visits and duplicates. Cleaning and mapping are real work.
3. **Paper first.** Protocols, SAPs and table shells are frozen with a git tag before a single result is generated.

## Running it

Requires Docker.

```sh
cp .env.example .env              # then set your own local passwords
docker compose up -d db           # start the clinical database (PostgreSQL 18)
docker compose run --rm analysis Rscript tests/run-tests.R        # 25 database checks
docker compose run --rm analysis Rscript tests/check-style.R      # lintr and styler
docker compose run --rm analysis Rscript -e 'targets::tar_make()' # the pipeline
docker compose run --rm analysis bash -c 'cd docs/templates && quarto render'  # documents
```

`compose.yaml` starts the database and the analysis environment together. The analysis image pins R 4.6.1, the system libraries and every R package ([ADR 0012](docs/adr/0012-reproducible-environment.md)). The database has separate roles for loading and reading raw data and an append-only audit trail ([ADR 0013](docs/adr/0013-database-roles-and-audit-trail.md)). Continuous integration runs the same commands, in the same image, on every pull request (`.github/workflows/ci.yaml`).

## Third-party data

The benchmark uses the **CDISC SDTM/ADaM Pilot Project** (CDISCPILOT01), © CDISC, from [cdisc-org/sdtm-adam-pilot-project](https://github.com/cdisc-org/sdtm-adam-pilot-project) under the [CDISC Terms of Use](https://github.com/cdisc-org/sdtm-adam-pilot-project#terms-of-use).

The pilot data are de-identified legacy data from a real trial of transdermal xanomeline in Alzheimer's disease, provided by Eli Lilly and Company to the CDISC pilot. They are not simulated.

They are not redistributed in this repository. The pipeline downloads them from a pinned commit and verifies every file against [a manifest of hashes](data/external/cdiscpilot01-manifest.csv). It never modifies them. See [ADR 0015](docs/adr/0015-third-party-pilot-data.md).
